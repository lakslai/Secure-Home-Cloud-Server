# Secure Home Cloud

Простой статический сайт для GitHub Pages. Он использует Supabase Auth для входа, существующие таблицы `USER`, `FILE`, `STORAGE` из проекта и приватный bucket Supabase Storage для **демонстрационной** загрузки настоящих файлов. Домашний SSD в этой версии не подключён.

## Что работает после подключения

- Регистрация и вход по email и паролю.
- Список собственных файлов, поиск по названию и фильтр по типу.
- Загрузка файла до 50 MB, открытие, переименование и удаление.
- Счётчик файлов и суммарный размер из SQL-агрегации.

## Подключение Supabase

1. Откройте `supabase-setup.sql` и сравните названия столбцов со своей базой Assignment 4. Скрипт рассчитан на схему из PDF; **не запускайте его вслепую**, если база отличается или уже содержит собственные RLS policies. Пришлите мне Project URL и структуру таблиц, тогда я подгоню скрипт точно.
2. В Supabase SQL Editor выполните проверенный скрипт. Он добавляет связь аккаунта Auth с `USER`, закрытый bucket `home-files`, правила доступа к личным файлам и функцию статистики.
3. `config.js` уже содержит Project URL и **publishable key**, которые вы прислали. Эти данные видны посетителям статического сайта, поэтому доступ к личным файлам должен ограничиваться RLS. **Никогда не вставляйте `service_role` или secret key в сайт.**
4. В Supabase Authentication → URL Configuration укажите URL сайта в Site URL и Redirect URLs. При включённом подтверждении email пользователь получит письмо перед первым входом.
5. Откройте `index.html` через локальный сервер или GitHub Pages. Зарегистрируйтесь, загрузите небольшой файл и проверьте `FILE` и Storage в Supabase.

## GitHub Pages

Поместите файлы этой папки в корень репозитория. В GitHub: **Settings → Pages → Build and deployment → Deploy from a branch → main → /(root)**. После публикации добавьте адрес Pages в Supabase Redirect URLs. Сайт не требует сборки или npm.

## Что важно для защиты

В приложении действия связаны с базой: поиск выполняет `SELECT` с `WHERE`, статистика делает `COUNT` и `SUM`, загрузка создаёт запись через `INSERT`, переименование выполняет `UPDATE`, удаление выполняет `DELETE`. Файл при загрузке сохраняется в Supabase Storage. В исходной идее он должен храниться на домашнем SSD; для такой версии понадобится отдельный сервер на ноутбуке и VPN/HTTPS.

`config.js` содержит только публичный ключ. Защита данных зависит от правил RLS в Supabase. Перед публикацией следует проверить и убрать любые старые широкие policies для таблиц `USER`, `FILE`, `STORAGE` и bucket.
