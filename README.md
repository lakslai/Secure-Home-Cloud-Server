# Secure Home Cloud

Простой статический сайт для GitHub Pages. Он использует Supabase Auth для входа, существующие таблицы `USER`, `FILE`, `STORAGE` из проекта и приватный bucket Supabase Storage для **демонстрационной** загрузки настоящих файлов. Домашний SSD в этой версии не подключён.

## Что работает после подключения

- Регистрация и вход по email и паролю.
- Список собственных файлов, поиск по названию и фильтр по типу.
- Загрузка файла до 50 MB, открытие, переименование и удаление.
- Счётчик файлов и суммарный размер из SQL-агрегации.

## Подключение Supabase

Ошибка `Could not find the function public.app_ensure_user` означает, что настройка базы ещё не выполнена. Публичный ключ сайта не может создавать SQL-функции и политики: этот шаг выполняется владельцем проекта в SQL Editor.

1. Откройте **Supabase Dashboard → SQL Editor → New query**. Скопируйте **весь** файл `supabase-setup.sql`, вставьте и нажмите **Run**. Скрипт составлен по структуре таблиц из вашего Assignment 4 PDF; он сохраняет старые записи и добавляет отдельного пользователя для каждого аккаунта Supabase Auth. Если реальная база отличается от PDF, пришлите текст ошибки SQL Editor для точной правки.
2. После сообщения **Success** обновите сайт. Войдите, загрузите маленький файл и проверьте, что он появился в **Storage → home-files** и **Table Editor → FILE**. Поиск, счётчик, переименование и удаление должны менять реальные записи.
3. `config.js` уже содержит Project URL и **publishable key**, которые вы прислали. Эти данные видны посетителям статического сайта, поэтому доступ к личным файлам ограничивается RLS. **Никогда не вставляйте `service_role` или secret key в сайт.**
4. В Supabase **Authentication → URL Configuration** укажите адрес сайта в Site URL и Redirect URLs. При включённом подтверждении email пользователь получит письмо перед первым входом.

## GitHub Pages

Поместите **содержимое** этой папки (не саму папку) в корень репозитория. В GitHub: **Settings → Pages → Build and deployment → Deploy from a branch → main → /(root)**. После публикации добавьте адрес Pages в Supabase Redirect URLs. Сайт не требует сборки или npm.

## Что важно для защиты

В приложении действия связаны с базой: поиск выполняет `SELECT` с `WHERE`, статистика делает `COUNT` и `SUM`, загрузка создаёт запись через `INSERT`, переименование выполняет `UPDATE`, удаление выполняет `DELETE`. Файл при загрузке сохраняется в Supabase Storage. В исходной идее он должен храниться на домашнем SSD; для такой версии понадобится отдельный сервер на ноутбуке и VPN/HTTPS.

`config.js` содержит только публичный ключ. Защита данных зависит от правил RLS в Supabase. Перед публикацией следует проверить и убрать любые старые широкие policies для таблиц `USER`, `FILE`, `STORAGE` и bucket.
